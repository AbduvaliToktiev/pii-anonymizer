# pii-anonymizer

PII-шлюз между пользователем и Claude. Только бэкенд, без интерфейса.

```
Клиент (curl, Postman, ваше приложение)
   │  файл + вопрос
   ▼
pii-anonymizer ── шифрует ПДн ──► Claude (видит только [PERSON_K7M2QX9D], [SNILS_3FQ8ZB1M], ...)
   │                                    │
   │ ◄──────────── ответ с метками ─────┘
   │  восстанавливает метки → настоящие данные
   ▼
Клиент получает ответ с реальными ФИО, телефонами и т.д.
```

Метка — тип и код, вычисленный из значения секретным ключом сервиса. Ключ и таблица
«метка → значение» остаются на этом компьютере: в модель, в сеть и в логи они не попадают.

## Стек

- Java 25, Spring Boot 4.1
- Apache POI 5.5: xlsx, xls, docx, doc, pptx
- odt — разбор zip и XML средствами JDK
- Apache PDFBox 3.0: pdf
- Anthropic Java SDK 3.3: Claude API (`claude-opus-5-5`)

## Запуск

Сервис слушает `http://127.0.0.1:8080`, только с этого компьютера. Ключ Claude API
(`ANTHROPIC_API_KEY`) нужен только для `/api/ask`; обезличивание файлов и шлюз для Claude Code
работают без него. Ключ создаётся в [Claude Console](https://console.anthropic.com/) → API Keys
и оплачивается отдельно от подписки Claude.

docker run -d --name pii-anonymizer -p 127.0.0.1:8080:8080 --env-file .env pii-anonymizer

Что внутри образа: сборка в `maven:3.9.11-eclipse-temurin-25`, запуск в `eclipse-temurin:25-jre-noble`
от непривилегированного пользователя. Ключ меток хранится
в томе `pii-data` (`/app/data/token.key`): он переживает пересборку и перезапуск контейнера, и коды
меток остаются прежними. Порт публикуется
только на `127.0.0.1` хоста: из сети шлюз недоступен, как и при обычном запуске. Тесты при сборке
образа не гоняются, их запускает `mvn test`.

> подменяет HTTPS-сертификаты и Maven внутри контейнера им не доверяет. Добавьте
> `repo.maven.apache.org` в исключения HTTPS-проверки антивируса или соберите jar локально
> (`mvn package`) и запускайте его без Docker.

### Настройки

`src/main/resources/application.yml`: модель и глубина рассуждений (`anonymizer.claude`),
режим дат рождения (`anonymizer.birth-date.mode`), адрес Anthropic API для шлюза
(`anonymizer.gateway.upstream-url`). Любую настройку можно переопределить
переменной окружения: `anonymizer.claude.effort` → `ANONYMIZER_CLAUDE_EFFORT`.

Ключ меток (`anonymizer.token`): по умолчанию файл `data/token.key`, он создаётся со случайным
ключом при первом запуске и в git не попадает. Свой ключ можно задать переменной
`ANONYMIZER_TOKEN_KEY` (base64, не короче 16 байт) — например, чтобы у нескольких копий сервиса
были одинаковые коды. Если ключ удалить или сменить, коды всех меток станут другими.

### Метки: ПДн шифруются ключом

Каждое найденное значение заменяется меткой `[ТИП_КОД]`, например `[PERSON_K7M2QX9D]`.
Код — первые 40 бит HMAC-SHA256 от значения на секретном ключе сервиса, записанные
8 символами base32 (без похожих на цифры I, L, O, U).

- **Наружу уходит только метка.** Без ключа по коду нельзя ни восстановить значение, ни проверить
  догадку («это Иванов?»): перебор по списку фамилий не поможет.
- **Одно значение — одна метка везде:** в документе, на всех листах Excel, в вопросе, в следующих
  запросах и после перезапуска. Поэтому модель может считать по человеку: сумма начислений,
  число записей, группировка по отделам — строки с одинаковой меткой относятся к одному человеку.
- **Разные написания — одна метка:** «+7 916 123-45-67» и «89161234567», «Иванов Иван Иванович»,
  «Иванову Ивану Ивановичу» и «Иванов И.И.» (см. ниже).
- **Расшифровка — только в сервисе.** Ответ модели приходит с метками, сервис подставляет
  настоящие значения по своей таблице в памяти и отдаёт клиенту уже расшифрованный ответ.
- Если коды двух разных значений совпали, второе получает код длиннее.

Стойкость: это ключевое хеширование (HMAC), а не шифрование для хранения. Оно защищает от модели
и от того, кто видит трафик: видно, что строки с одной меткой — один человек, но не видно, кто он.

### Дата рождения: метка с возрастом

Настройка `anonymizer.birth-date.mode` в `application.yml`:

| Режим | Что видит модель | Когда выбирать |
|---|---|---|
| `age` (по умолчанию) | `[BIRTHDATE_K7M2QX9D_AGE41]`: возраст в полных годах на сегодня | нужны вопросы «кто старше 35», средний возраст и т.п. |
| `date` | `[BIRTHDATE_K7M2QX9D]`: о дате ничего | возраст модели не нужен |

В обоих режимах метка восстанавливается в исходную дату, в том числе в файлах, которые
Claude Code правит через шлюз. Возраст считается из дат вида `12.03.1985`, `12/03/85`,
`1985-03-12`, `12 марта 1985 г.` и `datetime.datetime(1985, 3, 12, 0, 0)`. Если записан только
год («1985 г.р.») или даты не существует, метка выдаётся без возраста.

Возраст — тоже сведения о человеке: вместе с отделом и должностью он сужает круг. Если это
критично, включите `date`.

### Падежи, порядок слов и инициалы: одна метка

Один человек в документах записан по-разному. Все такие записи получают одну метку:

| Запись | Метка |
|---|---|
| Иванов Иван Иванович (в таблице) | `[PERSON_0EWSNYJS]` |
| Иванову Ивану Ивановичу (в тексте приказа) | `[PERSON_0EWSNYJS]` |
| Ивановым Иваном Ивановичем, об Иване Ивановиче Иванове | `[PERSON_0EWSNYJS]` |
| Иван Иванович Иванов | `[PERSON_0EWSNYJS]` |
| Иванов И.И., И. И. Иванов, Иванову И.И. | `[PERSON_0EWSNYJS]` |

**Как это работает.** У каждого слова ФИО отбрасывается падежное окончание («Иванову» → «иванов»,
«Анной» → «анн», «Ивановича» → «иванович», «Достоевского» → «достоевск»), основы сортируются —
получается ключ, одинаковый для всех падежей и порядков слов. Сокращения связываются по ключу
«основа фамилии + инициалы». Код метки вычисляется из этого ключа, поэтому одинаков в любом запросе.
Словаря имён нет: правила одинаково работают для русских, казахских, узбекских и других имён
на кириллице; имена на латинице только приводятся к нижнему регистру.

**Разные люди не склеиваются.** «Евгений Иванов» и «Евгения Иванова» после отбрасывания окончаний
совпадают, но это разные люди. Поэтому две разные записи, каждая из которых выглядит как
именительный падеж (как в колонке «ФИО»), получают разные метки, и записи с такой основой
дальше не склеиваются. То же для одинаковых инициалов: если есть «Иванов Иван Иванович»
и «Иванов Илья Игоревич», сокращение «Иванов И.И.», встреченное после второго, получает свою метку.

**Что восстанавливается.** Метка заменяется одной записью человека: полной (а не сокращением),
в именительном падеже, если она встречалась, иначе — первой. Поэтому «выдать премию [PERSON_…]»
превратится в «выдать премию Иванов Иван Иванович» — по смыслу верно, падеж не согласован.

**Что не склеивается:** родительный падеж мужского ФИО, совпадающий по виду с именительным женского
(«Иванова Ивана») — получает свою метку; ФИО без отчества с ФИО с отчеством («Иван Иванов»
и «Иванов Иван Иванович»); фамилия с одним инициалом («Иванов И.»).

**В шлюзе для Claude Code** каждое написание получает свою метку (`PseudonymRegistry(true)`):
правки файлов должны вернуться в исходном виде, «Иванову» — как «Иванову». Все формы при этом
тоже зашифрованы.

Код: основы и ключ — `PersonNames.stem`, `caseInsensitiveKey`, `looksNominative`; метки —
`PseudonymRegistry.personToken`; ключ кодов — `TokenKey`. Тесты: `PseudonymRegistryTest`.

### Падежи при поиске

Детекторы ФИО не требуют именительного падежа:

| Что | Как учитывается падеж | Пример |
|---|---|---|
| отчество | суффикс -вич/-вн/-ич/-ичн плюс до трёх букв окончания | Ивановича, Ивановной, Петровичу |
| имя и фамилия без отчества | падеж не важен: ищутся слова с заглавной буквы | Ивану Петрову, Марии Сидоровой |
| фамилия рядом с именем | любое слово с заглавной буквы рядом с «Имя Отчество»; рядом с одним именем — окончание из `Surnames.ENDING` с падежным хвостом | Иванову, Петровой, Достоевского |
| фамилия с инициалами | любое слово с заглавной буквы; при выборе между двумя словами — окончание из `Surnames.ENDING` | Иванову И.И., Петровой А.С. |

### Фамилия или нет: исключения в `Surnames.java`

Без NER-модели фамилию угадывают по соседству и окончанию: слово с заглавной буквы рядом
с именем («Анна Петрова») или с инициалами («Иванов И.И.», «И.И. Иванов»). Правила общие
для обоих детекторов ФИО и лежат в `src/main/java/ru/pii/anonymizer/detect/Surnames.java`:

- `ENDING` — окончания фамилий с падежными формами (-ов, -ин, -ский, -енко, -ук, -дзе…);
- `NOT_SURNAMES` — слова, которые стоят рядом с ФИО, но фамилией не бывают.

Исключения нужны прежде всего для слов, похожих на фамилию по окончанию. Без них
в «Гражданин Петров П.П.» под метку ушло бы «Гражданин П.П.», а настоящая фамилия осталась бы открытой.
Сейчас в списке: должности и роли (сотрудник, директор, инженер, исполнитель, клиент, пациент…),
обращения (уважаемый, господин, госпожа, товарищ, коллега) и слова вроде гражданин/гражданка,
мужчина, женщина, рядовой, старшина, пенсионер, сын, внук.

Если вокруг инициалов два слова с заглавной буквы («Подписал И.И. Иванов»), фамилией
считается то, что похоже на неё по окончанию. Если похожи оба или ни одно, берётся слово
перед инициалами.

**Как добавить исключение.** Впишите слово в `NOT_SURNAMES` строчными буквами **во всех нужных
падежах**: сравнивается точная форма слова.

```java
"гражданин", "гражданина", "гражданину", "гражданином", "гражданине",
```

Затем добавьте строку в тест `TextAnonymizerTest.findsRussianNames`, например
`"Гражданин Петров П.П. задержан | Гражданин Иванов Иван Иванович задержан"`, соберите проект
(`mvn package`) и перезапустите сервис.

Если, наоборот, настоящая фамилия не находится, допишите её окончание в `ENDING`.
Не вносите в `NOT_SURNAMES` слова, которые бывают фамилиями (Кузнец, Соловей, Мельник):
людей с такими фамилиями детектор перестанет находить.

## Форматы файлов

| Формат | Что обезличивается | Что сохраняется |
|---|---|---|
| xlsx, xls | ячейки, примечания, гиперссылки, колонтитулы листов, строки в кавычках внутри формул, автор | формулы, форматы, стили, листы, ширина колонок |
| docx | абзацы, таблицы (в т.ч. вложенные), колонтитулы, сноски, автор | оформление: ФИО, разбитое на фрагменты с разным оформлением, заменяется целиком |
| doc (Word 97–2003) | основной текст и таблицы; колонтитулы, сноски, примечания, надписи; автор, последний редактор и путь к шаблону (в т.ч. в служебной таблице файла) | оформление, таблицы, разделы |
| pptx | надписи, заполнители, таблицы, группы фигур, заметки докладчика; ссылки mailto с ПДн; миниатюра; автор | разметка слайдов, оформление фрагментов |
| odt | абзацы и заголовки (в т.ч. в таблицах, сносках), колонтитулы, ссылки; автор; миниатюра | структура архива и XML, стили |
| pdf | текст страниц и форм, примечания, ссылки mailto, закладки, значения полей форм; автор, название, тема; XMP | обрабатывается на месте: шрифты, вёрстка, картинки, таблицы, число страниц |

**PDF не пересобирается и не требует шрифтов.** ПДн ищутся в тексте страницы с учётом положения
символов: слово, которое Word разбил на фрагменты с разным оформлением, остаётся словом, а соседние
ячейки таблицы не склеиваются в «ФИО». Символы найденного значения удаляются из команд страницы,
а на их место ставится метка. Метка рисуется стандартным шрифтом Helvetica и сжимается по ширине
ровно до места исходного текста, поэтому текст после неё остаётся на месте. Это нужно потому, что
шрифты в PDF обычно встроены не целиком, а с буквами самого документа, и латиницы, цифр и скобок
метки в них может не быть. Весь остальной текст остаётся в своих шрифтах. Готовый файл проверяется
повторно: если детекторы в нём что-то находят, файл не отдаётся, а сервис отвечает ошибкой 422.
Сканы без текстового слоя по-прежнему отклоняются (нужен OCR).

**Формулы Excel не ломаются.** Формула остаётся формулой. Если в её сохранённом результате есть ПДн
(`=Сотрудники!B2`, `=ИНДЕКС(...)` с ФИО, `="Ответственный: "&B2`), обезличивается только результат;
строки в кавычках внутри формулы (`=СЧЁТЕСЛИ(A:A;"Иванов Иван Иванович")`) — тоже. Так как одно ФИО
на всех листах получает одну метку, ВПР, СУММЕСЛИ, СЧЁТЕСЛИ, ИНДЕКС/ПОИСКПОЗ по ФИО на обезличенном
файле дают те же результаты. Файл помечается на пересчёт при открытии. Проверено в Excel на книге
из 10 000 сотрудников: 50 049 формул, ни одной ошибки, итоги по отделам совпадают с оригиналом.

**Скрытые остатки удаляются.** Excel хранит текст ячеек в общей таблице строк, и после замены
старое ФИО осталось бы в файле невидимым; строки, на которые больше не ссылается ни одна ячейка,
удаляются из таблицы, ссылки ячеек перенумеровываются. В doc стирается служебная таблица
SttbfAssoc (автор, последний редактор), в pptx и odt — миниатюра первой страницы. Тесты проверяют
отсутствие ПДн не в тексте, а в байтах файла (`RawBytes`).

**Длина в колонтитулах doc.** В doc колонтитулы, сноски, примечания и надписи — части с жёсткими
границами, которые библиотека не пересчитывает. Там метка ставится, только если помещается в длину
исходного фрагмента, иначе фрагмент закрашивается звёздочками той же длины
(«Исполнитель: *************»). В основном тексте и таблицах doc — обычные метки.

Скорость: книга на 10 000 строк × 12 колонок обезличивается за 4–5 секунд.

## Структура проекта

Пакеты `ru.pii.anonymizer`:

| Пакет | Что внутри |

| `document` | обработчики форматов (xlsx, xls, docx, doc, pptx, odt, pdf), извлечение текста |
| `pseudonym` | метки: ключ кодов (`TokenKey`), реестр меток (`PseudonymRegistry`), восстановление ответа (`Restorer`) |
| `gateway` | разбор запросов и ответов Anthropic API для шлюза Claude Code (обезличивание, потоковое восстановление) |

|---|---|---|---|
| `AskController` | `POST /api/ask` | вопрос к Claude, можно с файлом: шифрует ПДн в файле и вопросе, отправляет в модель, возвращает ответ с настоящими данными | `AskService` |

| `ApiExceptionHandler` | — | превращает ошибки сервисов в ответы 400/413/415/422/502 в формате Problem Details | — |

## API

### `POST /api/ask` — вопрос к LLM через шлюз

`multipart/form-data`:

| Поле | Обязательное | Описание |
|---|---|---|
| `prompt` | да | вопрос; ПДн в нём тоже обезличиваются |
| `file` | нет | xlsx, xls, docx, doc, pptx, odt или pdf до 20 МБ |
| `showAnonymized` | нет | `true` — добавить в ответ то, что увидела модель |

Ответ:

```json
{
  "answer": "Больше всех получает Петрова Анна Сергеевна — 250 000 ₽",
  "model": "claude-opus-5-5",
  "found": {"PERSON": 4, "SNILS": 3, "PHONE": 3},
  "restored": 1,
  "unknownTokens": [],
  "inputTokens": 812,
  "outputTokens": 64,
  "truncated": false,
  "sentToLlm": "...",
  "llmAnswer": "Больше всех получает [PERSON_AYTYNSGA] — 250 000 ₽"
}
```

- `unknownTokens` — метки, которые модель выдумала или исказила; они остаются в ответе как есть.
- `sentToLlm` и `llmAnswer` возвращаются только при `showAnonymized=true`. Они нужны для проверки,
  что наружу ничего не утекло.

### `POST /api/anonymize` — только обезличить файл, без LLM

`multipart/form-data`, поле `file`. Возвращает обезличенный файл того же формата.
Заголовки: `X-Pii-Summary` (найдено по типам), `X-Pii-Replacements` (всего замен).

### `POST /api/anonymize/text` — только обезличить текст

JSON `{"text": "..."}` → `{"text", "found", "replacements"}`.

### Ошибки

Формат Problem Details (RFC 9457):

| Код | Причина |
|---|---|
| 400 | нет `prompt` или он пустой |
| 413 | файл больше 20 МБ |
| 415 | неподдерживаемый или переименованный файл |
| 422 | файл повреждён, защищён паролем или это скан без текста |
| 502 | Claude API недоступен, не принят ключ, исчерпан лимит или модель отказалась отвечать |

## Как файл передаётся в модель

Файл обезличивается в своём формате, затем из него извлекается текст. Таблицы Excel передаются
построчно через `|`. Текст вместе с вопросом уходит в модель. **Имя файла не передаётся**:
в нём тоже бывают фамилии.

Системный промпт объясняет модели, что метки нужно повторять дословно, не склоняя: иначе их не
получится заменить обратно.

Для Claude включён серверный fallback (`fallbacks: "default"`): если модель отклонит запрос
по соображениям безопасности, API повторит его на резервной модели.

## Известные ограничения

- Словаря имён нет: имя узнаётся по заглавным буквам. Поэтому одно слово посреди фразы
  («позвони Саше», «Сидоров сказал») не находится. Исключение — слово после должности или
  обращения: «Директор Олег», «Привет, Саша», «Mr. Smith».
- Два названия подряд с заглавной буквы принимаются за имя: «Microsoft Excel», «Нижний Новгород»
  без «г.», «Премия Анне Петровой» в начале фразы. Наружу при этом ничего не утекает, а при
  восстановлении ответа слова вернутся на место. Не трогаются названия после «г.», «ул.», «ООО»
  и т.п., в кавычках и в заголовках markdown.
- Имя, записанное целиком заглавными («ИВАНОВ ИВАН»), не находится (кроме колонки «ФИО» в таблицах).
- Две разные записи в именительном падеже с общей основой (Евгений Иванов и Евгения Иванова) — разные метки; родительный падеж мужского ФИО может не склеиться с именительным (см. «Падежи, порядок слов и инициалы»).
- Если модель просклоняет метку («[PERSON_K7M2QX9D]у»), окончание останется в ответе после подстановки.
- Номера договоров не ищутся. ИНН организаций тоже заменяются.
- Не поддерживаются: сканы, архивы, ods, odp, ppt (PowerPoint 97–2003).
- Не обрабатываются: картинки и диаграммы в документах, названия листов Excel, кэш сводных таблиц Excel.
- `/api/ask` возвращает ответ целиком, без потоковой передачи (шлюз для Claude Code — потоком).
- **Сервис не перехватывает claude.ai и десктопное приложение Claude**: файл, загруженный туда,
  уходит в Anthropic напрямую. Через шлюз проходят только запросы к `/api/*` и Claude Code,
  настроенный на шлюз (см. ниже).

## Шлюз для Claude Code

Claude Code в терминале или в VS Code можно направить через сервис:

```
Claude Code ──► pii-anonymizer (127.0.0.1:8080) ──► api.anthropic.com
 подписка или ключ      обезличивает запрос              видит только метки
  ◄── настоящие данные ── восстанавливает ответ ◄──
```

### Настройка

Запустите сервис (Docker, IDEA или `java -jar`) и направьте Claude Code на шлюз переменной
`ANTHROPIC_BASE_URL`. Постоянно для этого проекта — файлом `.claude/settings.local.json` в корне:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:8080"
  }
}
```

Файл личный и в `.gitignore`. Если его нет (свежий клон), создайте с этим содержимым.
После этого обычный `claude`, запущенный в папке проекта, всегда идёт через шлюз.

Разово, из любой папки (переменная действует только в этом окне PowerShell):

```powershell
$env:ANTHROPIC_BASE_URL = "http://127.0.0.1:8080"; claude
```

Авторизация — на выбор:
- **API-ключ** (оплата по балансу в [Claude Console](https://console.anthropic.com/)):
  задайте один раз `setx ANTHROPIC_API_KEY "sk-ant-..."` и перезапустите терминал и IDEA.
  При первом запуске Claude Code спросит, использовать ли ключ, — ответьте «да».
- **Подписка** Claude Pro/Max: не задавайте ключ, в первый раз выполните `/login`.

Учтите:
- **Без шлюза Claude Code в этой папке не работает**: запросы на `127.0.0.1:8080` упадут,
  в обход шлюза ничего не уйдёт. Сначала запустите сервис.
- Коды меток не зависят от перезапуска (ключ хранится в `data/token.key`), поэтому сеанс Claude Code
  переживает перезапуск шлюза: история диалога приходит с настоящими значениями и шифруется теми же кодами.

### Как это работает

- **Файлы на диске не меняются.** Обезличивается только трафик: содержимое прочитанных файлов,
  вывод команд, сообщения, системный промпт и вся история диалога.
- **Правки возвращаются с настоящими данными.** Если Claude пишет или правит файл с меткой
  `[PERSON_K7M2QX9D]`, шлюз подставит настоящее значение до того, как правка дойдёт до Claude Code.
  Каждое написание получает свою метку, поэтому «8-916-…» вернётся именно как «8-916-…».
- Авторизация (подписка или ключ) пересылается как есть, шлюз её не хранит и не логирует.
- Блоки размышлений модели не меняются: они подписаны, и изменение сломало бы диалог.
- **Картинки не передаются** (их нельзя обезличить), вместо них модель видит пометку.
  PDF передаётся как обезличенный текст.
- **Запросы без ПДн проходят как есть.** Шлюз ничего не блокирует: каждый запрос проверяется,
  найденные ПДн заменяются метками, остальной текст уходит без изменений.

Строка лога на каждый запрос к модели:

```
Шлюз: POST /v1/messages → 200 | файлы: C:\work\Зарплаты.xlsx | новые ПДн: PERSON=4, PHONE=3 | всего значений в реестре: 91
```

| Часть | Что значит |
|---|---|
| `POST /v1/messages → 200` | запрос Claude Code переслан в Anthropic, ответ 200 — успешно (`count_tokens` — подсчёт токенов) |
| `файлы` | что Claude Code прочитал в этом шаге: путь к файлу (Read, Edit, Write) или имя инструмента (Bash, Grep); `нет` — обычная реплика |
| `новые ПДн` | сколько значений каждого типа впервые встретилось в этом запросе; `нет` — новых ПДн не было |
| `всего значений в реестре` | сколько разных значений ПДн шлюз зашифровал с момента запуска |

Сами значения ПДн в лог не пишутся.

Ограничения:
- Работает в Claude Code в терминале и в VS Code. **Десктопное приложение Claude и claude.ai
  через шлюз не идут**: в десктопном приложении `ANTHROPIC_BASE_URL` игнорируется.
- Шлюз находит только то, что умеют детекторы (см. таблицу выше). Например, фамилия без имени
  уйдёт как есть.
- Шлюз видит только то, что вывел инструмент. Если Claude читает xlsx/docx как **сырой XML**,
  часть данных не распознаётся: дата рождения в Excel лежит отдельно от заголовка колонки
  (или числом вроде `31118`), а ФИО в Word бывает разорвано тегами на куски. Надёжнее, когда файл
  читается как таблица или текст (pandas, python-docx). Если скрипт сам преобразует значения
  (разбивает на буквы, кодирует), шлюз их тоже не узнает.

## Примеры

Вымышленные ПДн; СНИЛС и ИНН с верными контрольными суммами. Всё лежит в `samples/`:

| Файл | Что внутри |
|---|---|
| `Сотрудники_10000.xlsx` | 4 листа: «Сотрудники» (10 000 строк: ФИО, дата рождения, СНИЛС, ИНН, телефон, email, адрес, отдел, оклад), «Начисления» (ВПР по ФИО, премия, НДФЛ), «Итоги по отделам» (СЧЁТЕСЛИ, СУММЕСЛИ), «Справка» (ИНДЕКС/ПОИСКПОЗ, сцепка с ФИО, СЧЁТЕСЛИ с ФИО в кавычках, примечание, колонтитул) |
| `Сотрудники_3000.xls` | то же в формате Excel 97–2003 на 3 000 строк |
| `Зарплаты.xlsx`, `Зарплаты.xls` | короткая таблица с примечанием |
| `Итоги квартала.pptx` | 2 слайда: ФИО в разных падежах и разбитое на фрагменты, таблица, заметки, ссылка mailto |
| `Приказ о премировании.docx/.doc/.odt/.pdf` | ФИО в разных падежах и с инициалами, таблица, колонтитулы, иностранные имена |
| `Трудовой договор.docx/.doc/.odt/.pdf` | паспорт, СНИЛС, адрес, дата рождения, ФИО во фрагментах с разным оформлением |
| `Служебная записка.pdf` | простой текстовый PDF |

PDF из Word (`Приказ о премировании.pdf`, `Трудовой договор.pdf`) — самые близкие к реальным:
шрифты встроены не целиком, слова разбиты на фрагменты, есть таблица.

Сгенерировать заново xlsx, xls, pptx, docx и `Служебная записка.pdf`:
`mvn test -Dtest=SampleFilesWriter -Dsamples.dir=samples -Dsurefire.failIfNoSpecifiedTests=false`

doc, odt и pdf делает Word: откройте `.docx` и сохраните как «Документ Word 97–2003», «Текст OpenDocument» и PDF.
Word записывает в файл имя пользователя компьютера, поэтому после сохранения выполните
`mvn test -Dtest=WordSamplesScrubber -Dscrub.dir=samples -Dsurefire.failIfNoSpecifiedTests=false` —
утилита поставит вымышленного автора.

## Ручная проверка

1. Запустить сервис с ключом (см. «Запуск»). В PowerShell вызывайте `curl.exe`, а не `curl`:
   `curl` там — псевдоним `Invoke-WebRequest`.
2. Задать вопрос по файлу и посмотреть, что увидела модель:
   ```bash
   curl -F "file=@samples/Зарплаты.xlsx" -F "prompt=Кто получает больше всех и какая средняя зарплата по отделам?" -F "showAnonymized=true" http://localhost:8080/api/ask
   ```
   Проверить:
   - в `sentToLlm` нет ни одной фамилии, СНИЛС, ИНН, телефона, email и номера карты — только метки;
   - зарплаты, отделы и должности в `sentToLlm` на месте;
   - в `llmAnswer` модель отвечает метками, а в `answer` вместо них настоящие ФИО;
   - `unknownTokens` пустой.
3. Вопрос с ПДн в самом тексте:
   ```bash
   curl -F "prompt=Составь письмо Петровой Анне Сергеевне, телефон +7 903 765-43-21" -F "showAnonymized=true" http://localhost:8080/api/ask
   ```
   В `sentToLlm` будут `[PERSON_…]` и `[PHONE_…]`, а в `answer` — настоящие имя и телефон.
4. То же для `.doc`, `.odt`, `.pptx` и `samples/Служебная записка.pdf`.
5. Только обезличить файл и открыть его в Excel или Word:
   ```bash
   curl -F "file=@samples/Зарплаты.xlsx" -o result.xlsx http://localhost:8080/api/anonymize
   ```
6. Ошибки: без `prompt` → 400; `.txt` → 415; без ключа или с неверным ключом → 502.
7. Проверить лог сервиса: в нём только статистика (`найдено [PERSON=4, ...]`) и ни одного
   настоящего значения.
