# pii-anonymizer

PII-шлюз между пользователем и Claude. Только бэкенд, без интерфейса.

```
Клиент (curl, Postman, ваше приложение)
   │  файл + вопрос
   ▼
pii-anonymizer ── обезличивает ──► Claude (видит только [PERSON_1], [SNILS_1], ...)
   │                                    │
   │ ◄──────────── ответ с метками ─────┘
   │  восстанавливает метки → настоящие данные
   ▼
Клиент получает ответ с реальными ФИО, телефонами и т.д.
```

Таблица «метка → значение» живёт только в памяти сервиса на время запроса. Во внешнюю модель
она не передаётся и в логи не пишется.

## Стек

- Java 25, Spring Boot 4.1
- Apache POI 5.5: xlsx, xls, docx
- Apache PDFBox 3.0: pdf
- Anthropic Java SDK 3.3: Claude API (`claude-opus-5-5`)

## Запуск

Сервис слушает `http://127.0.0.1:8080`, только с этого компьютера. Ключ Claude API
(`ANTHROPIC_API_KEY`) нужен только для `/api/ask`; обезличивание файлов и шлюз для Claude Code
работают без него. Ключ создаётся в [Claude Console](https://console.anthropic.com/) → API Keys
и оплачивается отдельно от подписки Claude.

## Что находится

| Тип | Пример | Как проверяется |
|---|---|---|
| `PERSON` | Иванов Иван Иванович, Петровой Анне Сергеевне, Иванов И.И. | эвристика по отчеству и инициалам |
| `PERSON` | Анне Петровой, Нурлан Абенов, Алиев Рашид оглы, John Smith, Директор Олег, Привет, Саша | без словаря: 2–4 слова подряд с заглавной буквы на любом языке; одно слово — только после должности или обращения; в Excel — ещё и вся колонка «ФИО» |
| `SNILS` | 112-233-445 95 | формат + контрольное число |
| `INN` | 7707083893, 500100732259 | 10 или 12 цифр + контрольные разряды |
| `PASSPORT` | 45 06 123456; «паспорт 4506123456» | формат; слитно — только рядом со словом «паспорт» |
| `PHONE` | +7 (916) 123-45-67, 8-916-123-45-67 | формат российского номера |
| `EMAIL` | ivanov@example.ru | формат |
| `CARD` | 4111 1111 1111 1111 | 16–19 цифр + алгоритм Луна |
| `BIRTHDATE` | дата рождения 12.03.1985, родилась 5 июля 1990 г., 1985 г.р. | дата только рядом со словом-признаком; даты договоров и выплат не трогаются |
| `ADDRESS` | 123456, г. Москва, ул. Ленина, д. 5, кв. 12 | улица + обязательный номер дома; улица без дома не заменяется |
| колонки таблиц | «ФИО», «Дата рождения», «Адрес» в Excel, CSV (`;` и `,`), markdown, выводе pandas и `print(row)` из openpyxl, включая `datetime.datetime(...)` | заголовок колонки → все значения под ним |
| числа Excel | СНИЛС/ИНН вида `1.2345678964E10` | научная запись разворачивается в цифры и проверяется контрольной суммой |

Одно значение получает одну метку в файле и в вопросе одновременно: если в вопросе
«Сколько получает Иванов Иван Иванович?», а в таблице есть такая строка, модель увидит
одну и ту же метку `[PERSON_1]`.

### Дата рождения: метка с возрастом

Настройка `anonymizer.birth-date.mode` в `application.yml`:

| Режим | Что видит модель | Когда выбирать |
|---|---|---|
| `age` (по умолчанию) | `[BIRTHDATE_n_AGE41]`: возраст в полных годах на сегодня | нужны вопросы «кто старше 35», средний возраст и т.п. |
| `date` | `[BIRTHDATE_n]`: о дате ничего | возраст модели не нужен |

В обоих режимах метка восстанавливается в исходную дату, в том числе в файлах, которые
Claude Code правит через шлюз. Возраст считается из дат вида `12.03.1985`, `12/03/85`,
`1985-03-12`, `12 марта 1985 г.` и `datetime.datetime(1985, 3, 12, 0, 0)`. Если записан только
год («1985 г.р.») или даты не существует, метка выдаётся без возраста.

Возраст — тоже сведения о человеке: вместе с отделом и должностью он сужает круг. Если это
критично, включите `date`.

### Полное ФИО и инициалы: одна метка

В документах один человек часто записан по-разному: в таблице полностью, в подписи
сокращённо. Чтобы модель понимала, что это один человек, такие записи получают одну метку:

```
Иванов Иван Иванович … приказ подписал Иванов И.И.
Иванов Иван Иванович           … приказ подписал Иванов Иван Иванович
```

**Как сопоставляются записи.** Каждая запись сводится к ключу «фамилия + первые буквы имени
и отчества» без учёта регистра. Поддерживаются формы:

| Запись | Ключ |
|---|---|
| Иванов Иван Иванович | иванов ии |
| Иван Иванович Иванов | иванов ии |
| Иванов И.И., Иванов И. И. | иванов ии |
| И.И. Иванов, И. И. Иванов | иванов ии |

Порядок, в котором записи встречаются в тексте, не важен. Если сокращение встретилось раньше
полного ФИО, метка всё равно общая, а при восстановлении ответа подставится полное ФИО.

**Одинаковые инициалы у разных людей.** Если в документе есть «Иванов Иван Иванович»
и «Иванов Илья Игоревич», они получают разные метки. Чьё сокращение «Иванов И.И.»,
понять нельзя, поэтому сокращения, встреченные после второго человека, получают
отдельную метку и не приписываются ни одному из них. Сокращения, встреченные до второго
человека, остаются за первым.

**Что не связывается:**
- падежные формы: «Иванова Ивана Ивановича» и «Иванов И.И.» получат разные метки;
- ФИО без отчества («Иван Иванов»), одна фамилия или одно имя;
- фамилия с одним инициалом («Иванов И.»).

**Где работает.** В `/api/ask`, `/api/anonymize`, `/api/anonymize/text`.
В шлюзе для Claude Code связка выключена: там каждое написание получает свою метку, чтобы
правки файлов возвращались в исходном виде (`PseudonymRegistry(true)`).

Код: ключ строит `PersonNames.surnameAndInitials`, метки выдаёт
`PseudonymRegistry.personToken`. Тесты: `TextAnonymizerTest.fullNameAndInitialsGetSameToken`,
`abbreviationIsRestoredAsFullName`, `ambiguousInitialsKeepPeopleApart`,
`exactSpellingKeepsAbbreviationSeparate`.

### Падежи в ФИО

**Находятся все падежи.** Детекторы ФИО не требуют именительного падежа:

| Что | Как учитывается падеж | Пример |
|---|---|---|
| отчество | суффикс -вич/-вн/-ич/-ичн плюс до трёх букв окончания | Ивановича, Ивановной, Петровичу |
| имя и фамилия без отчества | падеж не важен: ищутся слова с заглавной буквы, а не формы из словаря | Ивану Петрову, Марии Сидоровой |
| фамилия рядом с именем | любое слово с заглавной буквы рядом с «Имя Отчество»; рядом с одним именем — окончание из `Surnames.ENDING` с падежным хвостом | Иванову, Петровой, Достоевского |
| фамилия с инициалами | любое слово с заглавной буквы; при выборе между двумя словами — окончание из `Surnames.ENDING` | Иванову И.И., Петровой А.С. |

**Но разные падежи — разные метки.** Значение сравнивается в том виде, в каком записано,
лемматизации нет. «[PERSON_44]» и «[PERSON_45]» получат `Иванов Иван Иванович`
и `Петровой Анне Сергеевне`: модель не узнает, что это один человек. То же для связки с инициалами:
«Иванова Ивана Ивановича» не свяжется с «Иванов И.И.».

**Восстановление возвращает исходную форму.** Метка заменяется ровно тем текстом, который
был в документе. Если модель поставит `Иванов Иван Иванович` в другой падеж («отправить Иванов Иван Иванович»,
а в документе было «Ивану Иванову»), в ответе окажется «отправить [PERSON_46]» —
грамматически неверно, но по смыслу правильно. Если модель сама допишет окончание
к метке («Иванов Иван Ивановичу»), окончание останется в ответе после подстановки.

**Что делать.**
- Задавайте вопросы с ФИО в той же форме, что в документе, обычно в именительном падеже
  (как в колонке «ФИО»). Тогда метка в вопросе совпадёт с меткой в таблице.
- Чтобы связывать падежные формы, нужна морфология (например, pymorphy или LanguageTool
  для Java): ключ строился бы по начальной форме. Сейчас это не сделано — словари фамилий
  и склонение редких фамилий (Шевченко, Черных, Гоголь) дают много ошибок.

### Фамилия или нет: исключения в `Surnames.java`

Без NER-модели фамилию угадывают по соседству и окончанию: слово с заглавной буквы рядом
с именем («Анна Петрова») или с инициалами («Иванов И.И.», «И.И. Иванов»). Правила общие
для обоих детекторов ФИО и лежат в `src/main/java/ru/pii/anonymizer/detect/Surnames.java`:

- `ENDING` — окончания фамилий с падежными формами (-ов, -ин, -ский, -енко, -ук, -дзе…);
- `NOT_SURNAMES` — слова, которые стоят рядом с ФИО, но фамилией не бывают.

Исключения нужны прежде всего для слов, похожих на фамилию по окончанию. Без них
в «Гражданин Петров П.П.» под метку ушло бы «Гражданин П.П.», а настоящая фамилия осталась бы открытой.
Сейчас в списке: должности и роли (сотрудник, директор, инженер, исполнитель, клиент, пациент…),
обращения (уважаемый, господин, госпожа, товарищ, коллега) и слова вроде гражданин/гражданка,
мужчина, женщина, рядовой, старшина, пенсионер, сын, внук.

Если вокруг инициалов два слова с заглавной буквы («Подписал И.И. Иванов»), фамилией
считается то, что похоже на неё по окончанию. Если похожи оба или ни одно, берётся слово
перед инициалами.

**Как добавить исключение.** Впишите слово в `NOT_SURNAMES` строчными буквами **во всех нужных
падежах**: сравнивается точная форма слова.

```java
"гражданин", "гражданина", "гражданину", "гражданином", "гражданине",
```

Затем добавьте строку в тест `TextAnonymizerTest.findsRussianNames`, например
`"Гражданин Петров П.П. задержан | Гражданин Иванов Иван Иванович задержан"`, соберите проект
(`mvn package`) и перезапустите сервис.

Если, наоборот, настоящая фамилия не находится, допишите её окончание в `ENDING`.
Не вносите в `NOT_SURNAMES` слова, которые бывают фамилиями (Кузнец, Соловей, Мельник):
людей с такими фамилиями детектор перестанет находить.

## API

### `POST /api/ask` — вопрос к LLM через шлюз

`multipart/form-data`:

| Поле | Обязательное | Описание |
|---|---|---|
| `prompt` | да | вопрос; ПДн в нём тоже обезличиваются |
| `file` | нет | xlsx, xls, docx или pdf до 20 МБ |
| `showAnonymized` | нет | `true` — добавить в ответ то, что увидела модель |

Ответ:

```json
{
  "answer": "Больше всех получает Петрова Анна Сергеевна — 250 000 ₽",
  "model": "claude-opus-5-5",
  "found": {"PERSON": 4, "SNILS": 3, "PHONE": 3},
  "restored": 1,
  "unknownTokens": [],
  "inputTokens": 812,
  "outputTokens": 64,
  "truncated": false,
  "sentToLlm": "...",
  "llmAnswer": "Больше всех получает [PERSON_2] — 250 000 ₽"
}
```

- `unknownTokens` — метки, которые модель выдумала или исказила; они остаются в ответе как есть.
- `sentToLlm` и `llmAnswer` возвращаются только при `showAnonymized=true`. Они нужны для проверки,
  что наружу ничего не утекло.

### `POST /api/anonymize` — только обезличить файл, без LLM

`multipart/form-data`, поле `file`. Возвращает обезличенный файл того же формата.
Заголовки: `X-Pii-Summary` (найдено по типам), `X-Pii-Replacements` (всего замен).

### `POST /api/anonymize/text` — только обезличить текст

JSON `{"text": "..."}` → `{"text", "found", "replacements"}`.

### Ошибки

Формат Problem Details (RFC 9457):

| Код | Причина |
|---|---|
| 400 | нет `prompt` или он пустой |
| 413 | файл больше 20 МБ |
| 415 | неподдерживаемый или переименованный файл |
| 422 | файл повреждён, защищён паролем или это скан без текста |
| 502 | Claude API недоступен, не принят ключ, исчерпан лимит или модель отказалась отвечать |

## Как файл передаётся в модель

Файл обезличивается в своём формате, затем из него извлекается текст. Таблицы Excel передаются
построчно через `|`. Текст вместе с вопросом уходит в модель. **Имя файла не передаётся**:
в нём тоже бывают фамилии.

Системный промпт объясняет модели, что метки нужно повторять дословно, не склоняя: иначе их не
получится заменить обратно.

Для Claude включён серверный fallback (`fallbacks: "default"`): если модель отклонит запрос
по соображениям безопасности, API повторит его на резервной модели.

## Известные ограничения

- Словаря имён нет: имя узнаётся по заглавным буквам. Поэтому одно слово посреди фразы
  («позвони Саше», «Сидоров сказал») не находится. Исключение — слово после должности или
  обращения: «Директор Олег», «Привет, Саша», «Mr. Smith».
- Два названия подряд с заглавной буквы принимаются за имя: «Microsoft Excel», «Нижний Новгород»
  без «г.», «Премия Анне Петровой» в начале фразы. Наружу при этом ничего не утекает, а при
  восстановлении ответа слова вернутся на место. Не трогаются названия после «г.», «ул.», «ООО»
  и т.п., в кавычках и в заголовках markdown.
- Имя, записанное целиком заглавными («ИВАНОВ ИВАН»), не находится (кроме колонки «ФИО» в таблицах).
- Падежные формы одного человека получают разные метки: «Иванов Иван Иванович» и «Иванову Ивану Ивановичу».
- Если модель просклоняет метку («[PERSON_1]у»), окончание останется в ответе после подстановки.
- Номера договоров не ищутся. ИНН организаций тоже заменяются.
- Не поддерживаются: .doc, .pptx, .odt, сканы, архивы.
- `/api/ask` возвращает ответ целиком, без потоковой передачи (шлюз для Claude Code — потоком).
- **Сервис не перехватывает claude.ai и десктопное приложение Claude**: файл, загруженный туда,
  уходит в Anthropic напрямую. Через шлюз проходят только запросы к `/api/*` и Claude Code,
  настроенный на шлюз (см. ниже).

## Шлюз для Claude Code

Claude Code в терминале или в VS Code можно направить через сервис:

```
Claude Code ──► pii-anonymizer (127.0.0.1:8080) ──► api.anthropic.com
 подписка или ключ      обезличивает запрос              видит только метки
  ◄── настоящие данные ── восстанавливает ответ ◄──
```

### Настройка

Запустите сервис (Docker, IDEA или `java -jar`) и направьте Claude Code на шлюз переменной
`ANTHROPIC_BASE_URL`. Постоянно для этого проекта — файлом `.claude/settings.local.json` в корне:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:8080"
  }
}
```

Файл личный и в `.gitignore`. Если его нет (свежий клон), создайте с этим содержимым.
После этого обычный `claude`, запущенный в папке проекта, всегда идёт через шлюз.

Разово, из любой папки (переменная действует только в этом окне PowerShell):

```powershell
$env:ANTHROPIC_BASE_URL = "http://127.0.0.1:8080"; claude
```

Авторизация — на выбор:
- **API-ключ** (оплата по балансу в [Claude Console](https://console.anthropic.com/)):
  задайте один раз `setx ANTHROPIC_API_KEY "sk-ant-..."` и перезапустите терминал и IDEA.
  При первом запуске Claude Code спросит, использовать ли ключ, — ответьте «да».
- **Подписка** Claude Pro/Max: не задавайте ключ, в первый раз выполните `/login`.

Учтите:
- **Без шлюза Claude Code в этой папке не работает**: запросы на `127.0.0.1:8080` упадут,
  в обход шлюза ничего не уйдёт. Сначала запустите сервис.
- Пока правите сам шлюз и часто его перезапускаете, уберите `ANTHROPIC_BASE_URL` из файла:
  перезапуск сбрасывает таблицу меток и ломает текущий сеанс.

### Как это работает

- **Файлы на диске не меняются.** Обезличивается только трафик: содержимое прочитанных файлов,
  вывод команд, сообщения, системный промпт и вся история диалога.
- **Правки возвращаются с настоящими данными.** Если Claude пишет или правит файл с меткой
  `[PERSON_1]`, шлюз подставит настоящее значение до того, как правка дойдёт до Claude Code.
  Каждое написание получает свою метку, поэтому «8-916-…» вернётся именно как «8-916-…».
- Авторизация (подписка или ключ) пересылается как есть, шлюз её не хранит и не логирует.
- Блоки размышлений модели не меняются: они подписаны, и изменение сломало бы диалог.
- **Картинки не передаются** (их нельзя обезличить), вместо них модель видит пометку.
  PDF передаётся как обезличенный текст.

Ограничения:
- Работает в Claude Code в терминале и в VS Code. **Десктопное приложение Claude и claude.ai
  через шлюз не идут**: в десктопном приложении `ANTHROPIC_BASE_URL` игнорируется.
- Таблица меток живёт в памяти шлюза. После перезапуска шлюза начните новый сеанс Claude Code,
  иначе метки в истории разойдутся с новыми.
- Шлюз находит только то, что умеют детекторы (см. таблицу выше). Например, фамилия без имени
  уйдёт как есть.
- Шлюз видит только то, что вывел инструмент. Если Claude читает xlsx/docx как **сырой XML**,
  часть данных не распознаётся: дата рождения в Excel лежит отдельно от заголовка колонки
  (или числом вроде `31118`), а ФИО в Word бывает разорвано тегами на куски. Надёжнее, когда файл
  читается как таблица или текст (pandas, python-docx). Если скрипт сам преобразует значения
  (разбивает на буквы, кодирует), шлюз их тоже не узнает.

## Ручная проверка

Примеры файлов с вымышленными ПДн лежат в `samples/`. Сгенерировать заново:
`mvn test -Dtest=SampleFilesWriter -Dsamples.dir=samples -Dsurefire.failIfNoSpecifiedTests=false`

1. Запустить сервис с ключом (см. «Запуск»). В PowerShell вызывайте `curl.exe`, а не `curl`:
   `curl` там — псевдоним `Invoke-WebRequest`.
2. Задать вопрос по файлу и посмотреть, что увидела модель:
   ```bash
   curl -F "file=@samples/Зарплаты.xlsx" -F "prompt=Кто получает больше всех и какая средняя зарплата по отделам?" -F "showAnonymized=true" http://localhost:8080/api/ask
   ```
   Проверить:
   - в `sentToLlm` нет ни одной фамилии, СНИЛС, ИНН, телефона, email и номера карты — только метки;
   - зарплаты, отделы и должности в `sentToLlm` на месте;
   - в `llmAnswer` модель отвечает метками, а в `answer` вместо них настоящие ФИО;
   - `unknownTokens` пустой.
3. Вопрос с ПДн в самом тексте:
   ```bash
   curl -F "prompt=Составь письмо Петровой Анне Сергеевне, телефон +7 903 765-43-21" -F "showAnonymized=true" http://localhost:8080/api/ask
   ```
   В `sentToLlm` будет `[PERSON_1]` и `[PHONE_1]`, а в `answer` — настоящие имя и телефон.
4. То же для `samples/Трудовой договор.docx` и `samples/Служебная записка.pdf`.
5. Только обезличить файл и открыть его в Excel или Word:
   ```bash
   curl -F "file=@samples/Зарплаты.xlsx" -o result.xlsx http://localhost:8080/api/anonymize
   ```
6. Ошибки: без `prompt` → 400; `.txt` → 415; без ключа или с неверным ключом → 502.
7. Проверить лог сервиса: в нём только статистика (`найдено [PERSON=4, ...]`) и ни одного
   настоящего значения.
